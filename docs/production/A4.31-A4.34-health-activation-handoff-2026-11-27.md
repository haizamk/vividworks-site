## Current production boundary

The following is the **intended and configured** exposure state after A4.31–A4.34:

1. **Only canonical GET `/api/health`** (original `$request_uri` `/api/health` with optional query string) is routed to Laravel via PHP-FPM on HTTPS.
2. **HEAD and all non-GET methods** on the health path return **405** before FastCGI where the health `location` applies; port 80 rejects non-GET health with **405** (no redirect).
3. **All other application paths** (including `/`, contact, inquiries, design-generation, design-callback, storage routes, other `.php` files, favicon, robots) remain **blocked at Nginx** (503/404/deny) per the controlled-exposure vhost.
4. **No production write endpoint** has been intentionally opened or end-to-end tested as part of this checkpoint sequence.
5. **No W2 (n8n) workflow** publication is implied or completed by this handoff.
6. **No Foundation & Identity** implementation or migration is approved by this checkpoint.
7. **Do not treat the API or platform as fully production-ready** — only the health probe activation is in scope.

Database backups from **A4.21B** (`public` schema dump under `/home/admin/backups/vividworks-production/`) are separate rollback data and are not superseded by this handoff.
